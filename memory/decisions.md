# Ключевые решения

Формат: дата — решение — причина — альтернатива и почему отклонена.

| Дата | Решение | Причина | Отклонённая альтернатива |
|---|---|---|---|
| 2026-09-12 | Скиллы — в `skills/` в корне, `.kimi-code/skills/` убирается | Универсальность под любой агент, один источник истины | Оставить `.kimi-code/skills/` ради авто-подхвата Kimi — привязка к одному harness'у |
| 2026-09-12 | Реестр скиллов — `skills/skills.md`; AGENTS.md только ссылается на папку | AGENTS.md не разрастается, список скиллов живёт рядом со скиллами | Перечислять скиллы прямо в AGENTS.md — дублирование и рассинхрон |
| 2026-09-12 | Правка плана — только после подтверждения оператора, без исключений | Оператор держит контроль над целью | Разрешить агенту тактические правки самостоятельно — отклонено оператором |
| 2026-09-12 | Приёмка — агент предлагает варианты проверки, оператор выполняет и подтверждает; по подзадачам или целиком | Пошаговая видимость прогресса, раннее catching проблем | Само-приёмка агентом без оператора — нет независимой проверки |
| 2026-10-04 | В `skills/` добавлены `ponytail` и `ponytail-review` — дословные копии из DietrichGebert/ponytail (MIT); адаптация только frontmatter (`argument-hint` → `arguments`) + строка-атрибуция | Проверенный анти-оверинжиниринг для код-задач; дословность = дешёвый diff-синк с апстримом | Перевод на русский — дрейф при обновлениях; все 6 скиллов комплекта — лишний контекст без подтверждённой боли |
| 2026-10-04 | Авто-подхват скиллов в Kimi Code: `setup.sh` создаёт `.kimi-code/skills/` с симлинками на `skills/*`; симлинки в `.gitignore` (не коммитятся), health_check их валидирует | Скиллы должны попадать в контекст автоматически, а не по дисциплине модели; источник истины остаётся `skills/`, симлинки — генерируемое окружение, как `.env` (решение 2026-09-12 про «убрать .kimi-code/skills» не отменяется: дублирования нет) | Коммитить симлинки в git — ломается checkout на Windows; `extra_skill_dirs` в config.toml — привязка к одному harness'у вне репозитория |
